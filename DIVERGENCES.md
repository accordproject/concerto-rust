| DV-013 | ts-bug | `ClassDeclaration.getProperties`, `getProperty` and `getIdentifierFieldName` recurse into the super type with no cycle check, so a cyclic inheritance chain (`A extends C`, `B extends A`, `C extends B`) makes `validateModelFiles`/`addCTOModel` fail with V8's `RangeError: Maximum call stack size exceeded` (PORTING.md 2.5). Ported as TS has it: the Rust walk is a loop with a visited set, and on a cycle returns `ErrorKind::JsRangeError` with that message (`engine-rangeerror-maxcallstack`, location `None`) instead of overflowing the native stack or reporting a cycle. `ModelManager.isAssignableTo` and `ClassDeclaration.getAllSuperTypeDeclarations` (`is_assignable_to`, `get_all_super_type_names`) reach the same cycle too: `getAllSuperTypeDeclarations` walks the chain iteratively rather than recursively, so on a cyclic chain it does not overflow the call stack — it loops until the process runs out of memory instead — and `isAssignableTo` calls it directly. Both are ported onto the same Rust `super_chain` loop here, so both return the identical `JsRangeError`, same code and message, as `getProperties`/`getProperty`/`getIdentifierFieldName` do. Unobservable: no fixture in the corpus drives either entry point into a cyclic chain, so this leg of the divergence is accepted on the strength of reading the TS source, not an observed corpus mismatch. Scope addition accepted by the maintainer on accordproject/concerto-rust#151. | An `IllegalModelException` naming the circular inheritance. | `conformance/ModelManager.validateModelFiles/b25d9dd5f7e2162ef0a0b2ee`, `343223828152dd93cffd4c24`, `ce4c72b99abd76dea938c762`; `conformance/ModelManager.addCTOModel/d85b28076a8ece00c558322c`; `model_manager::tests::circular_inheritance_is_a_range_error`, `error::tests::golden_engine_rangeerror_maxcallstack`. No fixture or test observes `is_assignable_to`/`get_all_super_type_names` on a cyclic chain (accordproject/concerto-rust#151). | `concerto-core/src/model_manager.rs` `super_chain`, `is_assignable_to`, `get_all_super_type_names` |
